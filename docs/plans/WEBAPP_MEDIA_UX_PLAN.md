## ۱. شناخت سیستم (Architecture)

```
کاربران: ربات تلگرام | مینی‌اپ (/app, X-Init-Data) | وب‌اپ/PWA (/student, کوکی hu_session) | پنل ادمین (/admin)
                         │
                 nginx (humsyar.ir) / Caddy (VPS compose)
                         │
          uvicorn api.main:app  ← یک پروسس، یک worker
          = backend/api/main.py (FastAPI) — ۳۸ روتر + سرو SPAها
                         │
     MongoDB "medicalbot":  bs_content / ref_files  ← فقط file_id تلگرام + متادیتا
                         │
     بایت فایل‌ها: سرورهای تلگرام  ←  getFile ابری (≤20MB)  ✗ برای فایل بزرگ
                                     MTProto/Kurigram (≤2GB) ✓ فقط در lecture_scribe استفاده می‌شود
     کش دیسک: /data/storage فقط برای PDF اصلی و صفحات رندرشده WebP
```

### مسیر فعلی پخش یک فایل
1. `ReaderScreen` → `reader.viewUrl()` → `GET /api/web/library/view-url/{scope}/{id}` (`web_reader.py:108-155`)
2. → `preview_url` (`resources.py:503` / `references.py:508`) → URL امضاشده با HMAC، اعتبار ۶۰۰ ثانیه
3. `<video src>` → `GET /api/resources/preview/{id}?uid&exp&token`
4. → `_preview_user` (چک توکن در **هر** درخواست) → rate-limit 300/h → `proxy_telegram_preview` (`telegram_send.py:174`)
5. → `telegram_file_url()` → **getFile ابری** → برای >20MB: `None` → **502** ✗

### چرا PDF کار می‌کند
PDFها زیر ۲۰MB هستند و از مسیر جداگانه (`_fetch_and_cache_master_pdf` → رندر WebP → کش دیسک) سرو می‌شوند. **اما PDF بالای ۲۰MB هم همین الان خراب است** (همان getFile ابری).

## ۲. فاز ۱ — رفع بحرانی پخش رسانه (بک‌اند) 🔴

### تصمیم معماری: «استریم MTProto با پشتیبانی Range + کش دیسک»

| گزینه | مزیت | عیب | انتخاب |
|---|---|---|---|
| A. Local Bot API Server (`--local`) | getFile تا ۲GB، `FileResponse` | زیرساخت جدید روی هر سه محیط (Railway/VPS/systemd)، `start_botapi.sh` الان `sleep infinity` است | ❌ فعلاً نه |
| B. دانلود کامل MTProto → کش → `FileResponse` | ساده، seek کامل | اولین پخش فایل ۵۳MB تا دانلود کامل منتظر می‌ماند | پشتوانه |
| **C. استریمر Range-aware با `Client.stream_media(offset, limit)` + نوشتن هم‌زمان در کش** | پخش فوری، seek کار می‌کند، از دفعهٔ دوم مستقیم از دیسک | کمی پیچیده‌تر | ✅ **پیشنهادی** |

`kurigram==2.2.26` (Pyrogram) و `tgcrypto` از قبل نصب‌اند — وابستگی جدید لازم نیست.

### کارها
1. **`backend/services/media_stream.py` (جدید)**
   - `resolve_media_source(file_id, size)`:
     - اگر فایل در کش دیسک کامل موجود است → `FileResponse` (Starlette خودش Range/206 را درست می‌دهد)
     - اگر `size ≤ 20MB` → همان پروکسی ابری فعلی
     - وگرنه → استریمر MTProto
   - استریمر: تبدیل `Range: bytes=a-b` به chunkهای ۱MB تلگرام (`offset = a // 1MiB`)، برش بایت‌های اول/آخر، پاسخ `206` با `Content-Range`/`Content-Length` دقیق (اندازه از `file_size` در DB).
   - کلاینت MTProto singleton مخصوص پروسس API (session در حافظه، توکن ربات) — جدا از پروسس ربات.
   - کش: `/data/storage/media/{file_unique_id}` با دانلود پس‌زمینه بعد از اولین درخواست + قفل per-file (جلوگیری از دانلود تکراری) + سقف حجم/LRU (مثلاً ۱۰GB، قابل تنظیم با env).
   - مدیریت `FILE_REFERENCE_EXPIRED` و `FloodWait`.
2. **`telegram_send.py`**
   - `proxy_telegram_preview` → واگذاری به `media_stream`.
   - `download_telegram_file` (PDF) هم برای >20MB به MTProto fallback کند.
3. **MIME درست**: `m4a/m4b → audio/mp4`، `mp4 → video/mp4`، `mp3 → audio/mpeg`، `ogg/opus → audio/ogg`، `webm`، `mov → video/quicktime` (Safari با `nosniff` سخت‌گیر است). از `canonical_audio_mime` موجود در `lecture_scribe.py` استفاده مجدد.
4. **توکن پخش**:
   - اعتبار توکن رسانه: ۶ ساعت (به‌جای ۱۰ دقیقه)، یا: اگر کوکی `hu_session` معتبر است، توکن منقضی هم پذیرفته شود (کاربر وب‌اپ همیشه کوکی دارد).
5. **Rate-limit**: درخواست‌های Range با `bytes=N-` که N>0 است شمرده نشوند؛ یا سقف ۳۰۰ → ۳۰۰۰.
6. **Gzip**: معاف کردن `video/*`, `audio/*`, `image/*` از `GZipMiddleware` (`main.py:359`).
7. **nginx**: برای `/api/*/preview/` → `proxy_buffering off; proxy_request_buffering off; proxy_read_timeout 3600s;` (`infrastructure/deployment/nginx-humsyar.conf`).
8. **تست‌ها** (الان صفر تست برای این مسیر):
   - Range `bytes=0-` / `bytes=1000-2000` / `bytes=-500` → 206 + هدرهای درست
   - فایل >20MB → مسیر MTProto (mock)
   - کش hit → FileResponse
   - توکن منقضی + کوکی معتبر → 200
   - MIME m4a → `audio/mp4`

**معیار پذیرش:** همان ویدیو ۳۶MB و ویس ۵۳MB در Chrome ویندوز، Safari آیفون/آیپد و Chrome اندروید پخش شوند، seek به وسط کار کند، و بعد از ۲۰ دقیقه توقف، ادامهٔ پخش قطع نشود.

## ۳. فاز ۲ — بازطراحی صفحهٔ پخش ویدیو و ویس 🎨

اصل: **یکپارچه با سیستم فعلی** — توکن‌های `--hym-*`، فونت Vazirmatn، تم تیره سرمه‌ای + اکسنت آبی/فیروزه‌ای، کارت‌های شیشه‌ای با radius موجود، RTL کامل.

### ۳.۱ پلیر ویدیو (`MediaView.tsx` → `VideoPlayer`)
- قاب `aspect-ratio: 16/9` با `max-height: calc(100dvh - هدر)`، گوشهٔ گرد `--hym-radius-xl`، سایهٔ نرم — دیگر نوار ۱۵۰px خالی نیست.
- **کنترل‌های سفارشی** (هم‌سبک پلیر صوتی):
  - پخش/توقف بزرگ مرکزی، ۱۰ ثانیه عقب/جلو (دابل‌تپ چپ/راست روی موبایل)، نوار زمان با **نمایش بافرشده** (`buffered`)، زمان به اعداد فارسی
  - سرعت ۰.۷۵/۱/۱.۲۵/۱.۵/۱.۷۵/۲، تمام‌صفحه، Picture-in-Picture (دسکتاپ/اندروید/iPadOS)
  - مخفی‌شدن خودکار کنترل‌ها بعد از ۳ ثانیه در حال پخش
- حالت‌ها: اسکلتون/اسپینر «در حال آماده‌سازی…» → بافر → خطا با **دکمهٔ «تلاش دوباره»** (refresh خودکار URL و برگشت به همان `currentTime`).
- iOS: `playsInline`، `webkit-playsinline`، fullscreen بومی (`webkitEnterFullscreen`).
- کارت اطلاعات زیر پلیر: نام جلسه، درس، حجم، مدت، «ادامه از ۱۲:۳۴» (chip قابل کلیک).

### ۳.۲ پلیر ویس (`AudioPlayer`)
- کارت مرکزی شیشه‌ای با:
  - آیکون/کاور گرادیانی (رنگ درس) + نام فایل + نام درس
  - **موج صوتی تزیینی** (bars متحرک هنگام پخش؛ با `prefers-reduced-motion` خاموش)
  - نوار پیشرفت بزرگ‌تر (حداقل ۴۴px ناحیهٔ لمس) با نمایش بافر
  - ردیف کنترل: ۱۵ ثانیه عقب · پخش/توقف (۶۴px) · ۱۵ ثانیه جلو — **جهت آیکون‌ها RTL‌آگاه**
  - سرعت، تایمر خواب (۱۵/۳۰/۶۰ دقیقه/پایان فایل)، علامت‌گذاری لحظه (bookmark → دفترچه من)
- جایگزینی `▶` و `❚❚` (که در iOS ایموجی می‌شوند) با آیکون SVG از اسپرایت موجود.
- **Media Session API**: عنوان/درس/آرت‌ورک روی لاک‌اسکرین iOS/Android و کلیدهای مدیا ویندوز/مک.
- پخش در پس‌زمینه وقتی صفحه قفل است (رفتار پیش‌فرض audio + Media Session).

### ۳.۳ مشترک
- میان‌برهای صفحه‌کلید: `Space/K` پخش، `←/→` ۱۰ ثانیه (معکوس‌شده برای RTL قابل بحث)، `F` تمام‌صفحه، `M` بی‌صدا، `<`/`>` سرعت.
- ذخیرهٔ موقعیت: هر ۵ ثانیه + `pagehide`/`visibilitychange` با `navigator.sendBeacon`؛ رفع باگ «بعد از seek به عقب ذخیره نمی‌شود» (`MediaView.tsx:54,172` — شرط `t - last > 5` با `Math.abs`).
- پیام‌های خطای دقیق: 401 (ورود دوباره)، 403 (اشتراک)، 429 (کمی صبر)، 502/503 (تلگرام در دسترس نیست — تلاش دوباره)، فرمت نامعتبر.

### ۳.۴ واکنش‌گرایی (breakpointهای فعلی پروژه)
| دستگاه | چیدمان |
|---|---|
| آیفون / اندروید (<768) | پلیر تمام‌عرض لبه‌به‌لبه، کنترل‌ها پایین با `env(safe-area-inset-bottom)`، چرخش افقی → تمام‌صفحه خودکار ویدیو |
| آیپد عمودی (768–1023) | پلیر وسط با حداکثر عرض ۹۰۰px، کارت اطلاعات زیر |
| آیپد افقی / لپ‌تاپ (1024–1279) | پلیر + پنل کناری (یادداشت/هوشیار) جمع‌شونده |
| دسکتاپ ویندوز/مک (≥1280) | پلیر بزرگ + پنل کناری باز، میان‌برها |

همه با `dvh` به‌جای `vh` و `safe-area-inset-left/right` برای آیفون افقی.

## ۴. فاز ۳ — سرعت بارگذاری ⚡

### PDF
- پیش‌بارگذاری ۲ صفحهٔ بعد/قبل، `loading="lazy"` + `decoding="async"` برای بقیه.
- `srcset` با دو رزولوشن (۱x/۲x) → تار نبودن در زوم و صفحه‌های رتینا.
- کش نکردن صفحه‌هایی که از دید خارج شده‌اند و دوباره دانلود نکردن (فعلاً unmount می‌شوند).
- `onError` روی تصویر صفحه → refresh توکن (الان ندارد: `ProtectedReaderView.tsx:726-743`).
- هدر `Cache-Control: private, max-age=86400, immutable` برای صفحات رندرشده (URL نسخه‌دار).

### ویدیو/ویس
- کش دیسک فاز ۱ → از دفعهٔ دوم سرعت کامل سرور.
- `preload="metadata"` حفظ شود؛ پیش‌گرم‌کردن کش وقتی کاربر صفحهٔ جلسه را باز می‌کند (prefetch پس‌زمینه برای فایل اول).
- (آینده) تبدیل به HLS با ffmpeg برای ویدیوهای خیلی بزرگ — خارج از این دور.

### باندل فرانت
- `React.lazy` برای routeها (الان یک باندل ۴۲۰KB)؛ جدا کردن Reader، Exam، AI.
- فشرده‌سازی لوگوی PNG ۲۵۳KB → WebP/SVG.
- حذف `pdfjs-dist` استفاده‌نشده و کد مرده `PDFDocument.ts`.
